# Gateway release smoke

Run `scripts/release_smoke.sh` from any directory. It validates discovery and executes every exact test in `tests/release_smoke_manifest.tsv`, stopping at the first failed test. The receipt records the discovered, executed, and passed counts plus each test result; set `RECEIPT_FILE` to choose its path. The release workflow uploads this receipt after its clean-tree preflight. The tests use the production Axum router, request middleware and handlers, and fresh synthetic SQLite databases. The HTTP tests use local storage and in-process requests; the private black-box test starts a local Gateway and connects over loopback. No test contacts APNs, FCM, WNS, a token service, or a deployed Gateway.

The profile covers authenticated Android/FCM registration, route setup, channel creation and rename, then positive message, thing (`create → update → archive → delete`), and event (`create → update → close`) lifecycles through their real HTTP handlers. It verifies durable sender status for every accepted action and correlates each operation ID with its pulled outer delivery ID; message, thing, and event ciphertext fixtures are checked byte-for-byte through provider pull. Canonical entity payloads also carry Gateway-derived lifecycle fields: thing `state` is `active` for create/update, `archived` for archive, and `deleted` for delete; event `event_state` is `ongoing` for create/update and `closed` for close. A second registered device joins after the message was accepted: it cannot pull or ACK that historical message, receives later entity deliveries, and can ACK its own copies without retiring the first subscriber's copies. The owner ACKs its full batch, duplicate ACKs remove nothing, and both queues are empty afterward. The loopback private WebSocket flow checks an invalid Hello token is rejected, a valid session receives ACK-timeout redelivery, and a reconnected session does not replay the acknowledged item. Remaining manifest rows cover thing-scoped event routing, malformed and identity-mismatched provider ingress, and sender op-ID idempotency/payload binding. Provider tokens and payloads are synthetic fixture values; ciphertext is opaque to Gateway and this profile proves pass-through, not client decryption.

Each router test creates a per-process SQLite file beneath `/tmp` using the same `Storage::new` initialization path as other router tests. The private black-box test starts one loopback Gateway and exercises one private delivery. The profile is six exact tests and uses no external database or provider credentials. The existing PostgreSQL/MySQL suites remain separate database-engine evidence; this command does not connect to those engines and its SQLite result is not cross-database parity evidence.

## Lifecycle field repair evidence (2026-10-05)

The loopback Apple integration exposed missing lifecycle state. The repair covers both domain generation (`state` / `event_state` derived from the accepted Thing/Event command) and dispatch's authoritative-field allowlists (`state`, `event_state`, `domain_action`). Custom sender fields cannot override those values. No storage migration or historical payload backfill is performed.

Fresh evidence on the local dirty candidate: dispatch filtering/custom-override tests 2/2; domain normalization regression 4/4; the full exact Gateway smoke profile 6/6 with zero ignored tests (`build/quality-results/lifecycle-fix-release-smoke.json`). The rebuilt Gateway also passed the real Apple service/ingress/Store integration at `../pushgo/build/quality-results/release-smoke/gateway-integration-20261005-030147/summary.json`, including exact archived Thing and closed independent/related Events. The client integration uses the same payload-to-entity routing entry as the App delegate; it does not claim native notification presentation.

No commit, push, remote CI, provider acceptance or production deployment was performed. Apple CI's paired revision must be advanced from the old baseline to a published fixed Gateway commit before release; the dirty local pass cannot validate the old remote pin.

## HTTP/2 dependency follow-up (2026-10-07)

Gateway, Token Service and Windows lockfiles now use registry h2 0.4.20 (previously 0.4.16); only the h2 version and checksum changed. The [upstream release](https://github.com/hyperium/h2/releases/tag/v0.4.20) fixes shutdown races, malformed GOAWAY/status/content-length handling, reset accounting and DATA frame budgeting. This does not claim a published security advisory or a new application-side defect.

`cargo test --locked --test blackbox_provider_ingress_ack -- --nocapture` now executes the same real-process provider ingress journey over HTTP/1.1 and forced HTTP/2, asserting the response protocol before registration/subscription/send/pull/ACK and queue-retirement checks. Both tests passed on Rust 1.97.1. The new HTTP/2 method is picked up by the existing all-targets preflight; the bounded six-row release-smoke manifest is unchanged. Token Service's locked all-targets/all-features tests passed 20/20. Evidence and dependency/source identities are in `build/quality-results/h2-0.4.20-summary.json`.

Windows received the identical registry-verified h2 lock entry without invoking Cargo, compilation or native tests. Android native and warp-link do not contain h2 in their lockfiles. Existing platform/native/provider/signed-release and old paired-CI pin limitations remain; no commit, push, remote CI or publication occurred.
